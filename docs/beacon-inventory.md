## ⚠️ ความเสี่ยงที่ยอมรับไว้ — password ค่าโรงงาน

**#2 และ #3 ยังใช้ password ค่าโรงงาน** — ใครก็ตามที่อยู่ในระยะ BLE และรู้ค่า default
ของรุ่นนี้ **เขียนทับ UUID / major / minor / TX power ได้ทั้งหมด**

- **ยอมรับได้เฉพาะระดับ POC ในออฟฟิศ** ที่ทุกตัวอยู่ในสายตาและไม่มีข้อมูลลูกค้าเกี่ยวข้อง
- 🔴 **ห้ามนำสภาพนี้ขึ้น pilot หรือสาขาจริงเด็ดขาด** — ต้องเปลี่ยน password ทุกตัว
  และบันทึกในตารางข้างบนก่อน

## หนี้ที่ผูกกับไฟล์นี้

1. ~~แมป tag → `major/minor` ให้ได้~~ **ปิดแล้ว 14 ก.ย. 2026** — ADR-20 หัวข้อ 1 (แก้ 11 ก.ย. 2026)
   เปลี่ยนให้ Android ถอด major/minor จากเฟรมโดยตรงแทนการอ่านจาก region spec แล้ว รอบเดินจริง
   12-14 ก.ย. 2026 (`docs/test-data/2026-09-14_android_overnight_proximity_redmi.log`, นับจากบรรทัด
   2207) ยืนยันว่า `beacon=` มีค่าจริงทุกบรรทัด (ไม่มี `n/a` เลย) — แมปได้ตรง ๆ จากการเห็น `beacon=`
   กับ `mac=` ในบรรทัดเดียวกัน: **`beacon=9902/2` คู่กับ `mac=55:50` เสมอ** และ **`beacon=9903/3` คู่กับ
   `mac=55:4D` เสมอ** (ยืนยันด้วย `grep -oE 'beacon=[^ ]+ mac=[^ ]+' | sort | uniq -c` → มีแค่ 3 คู่ค่า
   ที่เป็นไปได้: `beacon=9902/2 mac=55:50` (197 บรรทัด), `beacon=9903/3 mac=55:4D` (693 บรรทัด), และ
   `beacon=9903/3 mac=n/a` (464 บรรทัด — เฉพาะบรรทัด `reason=stale` ที่ไม่มี `ScanResult` สดคู่มาด้วยตาม
   ADR-20 หัวข้อ 3 ไม่ใช่ค่าที่ขัดแย้งกัน) **ไม่มีคู่ที่ผิด เช่น `beacon=9902/2 mac=55:4D` เลยสักบรรทัด**
   — ผลใส่ไว้ในตารางบีคอนด้านบนแล้ว
2. **calibration ขั้น 1** — วัดว่า `txPower = −51 dBm` ตรงกับ RSSI จริงที่ 1 เมตรไหม
   แล้วบันทึกส่วนต่างต่อบีคอนต่อสถานที่ลงตารางข้างบน
   (โปรโตคอลอยู่ที่ `test-checklists/android_background_scanning.md`) — **ยังไม่ปิด**
   สำหรับ #2/#3 แต่ได้ผลสังเกตเพิ่มสำหรับ **#4** แล้ว (15 ก.ย. 2026, ดูรายละเอียดเต็มที่
   `test-checklists/android_background_scanning.md` หัวข้อ "โปรโตคอล calibration"):
   ที่ตำแหน่งบนโต๊ะเดียวกับ #2/#3 (ระยะไม่ได้วัดแม่น — **ไม่ใช่ calibrate ที่ 1.00 ม.
   ตามโปรโตคอล**) `#4` RSSI **−75 dBm** / median **0.40 ม.** เทียบ `#3` RSSI **−35 dBm** /
   **0.23 ม.** และ `#2` RSSI **−46 dBm** / **0.63 ม.** — ระยะที่คำนวณได้อยู่ช่วงเดียวกัน
   แม้ RSSI ต่างกันถึง 30-40 dB **สถานะ: สอดคล้อง** (byte ในเฟรมสอดคล้องกับสัญญาณจริง
   ในระดับหยาบ) **ข้อสังเกต ไม่ใช่ข้อสรุป:** `#4` ส่งอ่อนกว่า `#2`/`#3` มาก อาจเหมาะเป็น
   บีคอนสำหรับจุดระยะสั้น (สอดคล้องกับแนวคิด "point beacon" ที่เคยหารือฝั่ง iOS — ยังไม่มี
   เอกสารอ้างอิงในโปรเจกต์ ณ ตอนนี้)
3. **เปลี่ยน password ทุกตัวก่อน pilot** และบันทึกในตาราง
4. **เติมค่าของ #1** เมื่อได้ตัวเครื่องกลับมา
5. **ยืนยันสาเหตุที่ #2/#3 มีความถี่ที่เห็นต่างกันมาก** — ดูหัวข้อ "🔎 ข้อสังเกตเชิงฮาร์ดแวร์" ด้านบน
   (เพิ่ม 14 ก.ย. 2026) ยังไม่มีข้อสรุป มีแค่สมมติฐานที่ต้องตรวจเพิ่ม
