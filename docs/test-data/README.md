# ข้อมูลดิบจากการทดสอบบนอุปกรณ์จริง

เก็บไฟล์ log ดิบจากการทดสอบไว้ในรีโป เพื่อให้**การวิเคราะห์ทำซ้ำได้**

## ทำไมต้อง commit ไฟล์ดิบ ไม่ใช่เก็บแต่ข้อสรุป

ข้อสรุปที่ไม่มีข้อมูลดิบกำกับคือข้อสรุปที่ตรวจย้อนกลับไม่ได้ — ถ้าวันหนึ่งพบว่าวิธี
คำนวณของเราผิด (นับ artifact รวมไปด้วย ตัดช่วงผิด ใช้เขตเวลาผิด) จะต้องไปทดสอบใหม่
ทั้งรอบ ซึ่งการทดสอบหนึ่งรอบใช้เวลาข้ามคืนและควบคุมเงื่อนไขให้เหมือนเดิมไม่ได้

## วิเคราะห์ยังไง

```bash
dart run tool/analyze_region_log.dart docs/test-data/<ไฟล์>.log
```

สคริปต์เดียวกันนี้ใช้กับ log ทุกรอบ — ตัวเลขจากคนละรอบจะเทียบกันได้ก็ต่อเมื่อคำนวณ
ด้วยวิธีเดียวกัน

## ตรวจก่อน commit ไฟล์ log ใหม่ทุกครั้ง

รูปแบบ log ปัจจุบันมีแค่ timestamp / ตัวระบุ process / ชนิด event / region
identifier / ข้อสรุป / สัญญาณดิบ — **ไม่มี** proximity UUID, major/minor, พิกัด,
หรือข้อมูลระบุตัวบุคคล

คีย์ในคอลัมน์สัญญาณดิบที่ตรวจแล้วของสองไฟล์ปัจจุบัน:
- iOS (5 คอลัมน์): `launchKey` `everActive` `state` `uptime` `monitoredRegions`
- Android (6 คอลัมน์): `procUuid` `pid` `uptimeMs` `receiverEntry` `everForeground`
  `activities` `state` `importance` `doze` `battOpt` `restoredRegions`

`procUuid` เป็น UUID ที่ **แอปสุ่มเองตอน process เริ่ม** ไม่ผูกกับเครื่องหรือผู้ใช้
และไม่ใช่ proximity UUID ของ beacon

ถ้ารูปแบบ log เปลี่ยนในอนาคต ต้องตรวจใหม่ก่อน commit:

```bash
grep -ciE "[0-9a-f]{8}-[0-9a-f]{4}|@|\+66|[0-9]{2}\.[0-9]{4}" <ไฟล์>.log
```

⚠️ **สิ่งที่ log ยังบอกได้แม้ไม่มีข้อมูลส่วนบุคคลตรง ๆ:** เขตเวลาของผู้ทดสอบ และ
ช่วงเวลาที่เครื่องอยู่นิ่ง/ถูกใช้งานในคืนนั้น — ยอมรับได้สำหรับ repo ภายในบริษัท
แต่ถ้าจะเผยแพร่ออกนอกองค์กร ต้องพิจารณาใหม่

## ความจริงภาคสนาม = เกณฑ์รับ

**`GROUND_TRUTH.md` ในโฟลเดอร์นี้บันทึกว่า "คำตอบที่ถูกต้อง" ของแต่ละไฟล์คืออะไร**
ซึ่งเป็นสิ่งที่ log เองบอกไม่ได้ · ทั้งสองไฟล์เก็บภายใต้เงื่อนไขที่รู้คำตอบล่วงหน้า
แน่นอน (**enter 1 ครั้ง · exit 0 ครั้ง**) จึงเป็น **เกณฑ์รับของชั้นกรองกลาง**
ตัวกรองที่อ่านสองไฟล์นี้แล้วไม่ได้ผลตามตารางในไฟล์นั้น = ยังไม่ผ่าน

**ห้ามลบสองไฟล์นี้ และห้ามแก้เนื้อไฟล์** — เก็บซ้ำไม่ได้ (ใช้เวลาข้ามคืนต่อรอบ
และคุมเงื่อนไขให้เหมือนเดิมไม่ได้)

|---|---|---|---|---|
| `2026-08-30_overnight_region_flapping.log` | 30 ส.ค. – 31 ส.ค. 2026 (14 ชม.) | **iOS** (CoreLocation) | มือถือวางนิ่ง จอดับ ล็อกเครื่อง แอปอยู่เบื้องหลัง K9P วางนิ่งไม่ถอดแบต ไม่มีใครขยับอะไร | region flapping ระยะยาว (เช็คลิสต์ข้อ 16), ค่า debounce ใน ADR-11, หลักฐานสนับสนุนข้อ 13 และข้อ 14 |
| `2026-09-01_android_overnight_region_flapping.log` | 1 ก.ย. – 2 ก.ย. 2026 (18 ชม. 33 น.) | **Android** (`PendingIntent` + นาฬิกาปลุก) | เงื่อนไขเดียวกันเป๊ะกับไฟล์บน — มือถือวางนิ่ง จอดับ K9P วางนิ่งข้าง ๆ ไม่มีใครแตะทั้งคืน | ADR-15 (`exitTimeoutSeconds` เป็นขอบล่าง), การเกาะกลุ่มของเวลา `exit` กับ batch ของ `AlarmManager`, เกณฑ์รับของชั้นกรองกลางฝั่ง Android |

⚠️ **ชื่อไฟล์ไม่สมมาตร** — ไฟล์ของ iOS ตั้งชื่อไว้ก่อนที่จะมีสองแพลตฟอร์ม จึงไม่มี
คำว่า `ios` อยู่ในชื่อ **จงใจไม่เปลี่ยนชื่อ** เพราะมีเอกสารหลายฉบับอ้างถึงด้วยชื่อนี้
(`ARCHITECTURE.md`, runbook, `tool/analyze_region_log.dart`) ไฟล์ใหม่ทุกไฟล์ต้องมี
แพลตฟอร์มอยู่ในชื่อ
