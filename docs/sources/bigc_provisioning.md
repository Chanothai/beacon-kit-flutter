# BigC Provisioning Values (bigc_provisioning)

**ประเภทเอกสาร: BigC internal provisioning record — ไม่ใช่ผลวิจัย vendor SDK**

ต่างจากไฟล์อื่นใน `docs/sources/` (เช่น `docs/sources/kkm_k9p.md` ซึ่งเป็นผลค้นคว้า SDK/GATT ของยี่ห้อภายนอก ผ่าน skill `beacon-sdk-verify`) ไฟล์นี้คือ**ค่าที่ BigC เอง generate ขึ้นมาใช้เป็นสคีมกลาง** ตาม ADR-5 ("BigC ID Scheme สำหรับ multi-vendor provisioning") ใน `ARCHITECTURE.md` — ไม่มี vendor ภายนอกให้ verify ในไฟล์นี้ ค่าทุกตัวในนี้คือของบริษัทเองที่ต้อง provision ลงอุปกรณ์ทุกยี่ห้อในฟลีต

**เหตุผลที่เก็บค่าไว้ที่นี่ (single source of truth) แทนที่จะห้ามเขียนค่าลงเอกสารเด็ดขาด:** ดู ARCHITECTURE.md หัวข้อ ADR-5 → "1. Proximity UUID — เดียวทั้งบริษัท (ข้อบังคับ)" — proximity UUID ของ iBeacon **ไม่ใช่ความลับ** (payload เป็น plaintext broadcast ที่ทุกอุปกรณ์ในระยะรับสัญญาณอ่านได้อยู่แล้วโดยไม่ต้องแฮ็ค) ความเสี่ยงตัวจริงคือเรื่อง**operational** — ถ้าค่าเดียวกันไปฝังกระจัดกระจายหลายที่ (โค้ด, เอกสารเก่า, README) การ rotate ค่าในอนาคตจะตามหา/แก้ให้ครบทุกที่ได้ยาก จึงกำหนดให้ไฟล์นี้เป็นที่เก็บค่าเดียวแทน **ห้ามเขียนค่า UUID นี้ซ้ำในเอกสารอื่นของโปรเจกต์ หรือ hardcode ซ้ำในซอร์สโค้ดที่ใดนอกเหนือจาก config ที่ backend/config service ควบคุม** (ตามที่ ADR-5 กำหนด)

### วิธี derive — UUID v5 จากชื่อโดเมนของบริษัท (ไม่ใช่ค่าสุ่ม)

ค่านี้**ไม่ได้สุ่ม** แต่ derive จากชื่อโดเมนของบริษัทด้วย UUID version 5
(RFC 4122 §4.3 — name-based, SHA-1):

```
namespace = NAMESPACE_DNS (6ba7b810-9dad-11d1-80b4-00c04fd430c8)
name      = "www.bigc.co.th"
```

**คำสั่งที่ verify ซ้ำได้จริง** (รันแล้วต้องได้ค่าเดียวกันเป๊ะทุกครั้ง บนทุกเครื่อง
ทุกภาษา — นี่คือคุณสมบัติของ v5 ไม่ใช่ความบังเอิญ):

```bash
python3 -c "import uuid; print(str(uuid.uuid5(uuid.NAMESPACE_DNS, 'www.bigc.co.th')).upper())"
# 89E2EDDA-D2C9-52F1-BC39-3489CC37E1EF
```

**ทำไมถึงเลือก v5 แทน `uuidgen` (v4 สุ่ม) — และราคาที่จ่าย**

- **ข้อดี:** ค่าที่ derive ได้**ตรวจซ้ำได้จากที่มา** ใครก็ตามที่สงสัยว่าค่าในไฟล์นี้
  ถูกพิมพ์ผิดหรือถูกแก้ระหว่างทาง รันคำสั่งข้างบนแล้วเทียบได้ทันที ต่างจากค่าสุ่ม
  ที่พิสูจน์ที่มาไม่ได้เลย — ถ้าไฟล์นี้หายหรือขัดแย้งกับที่อื่น ค่าที่ถูกต้อง
  สร้างกลับมาได้จากชื่อโดเมนตัวเดียว ไม่ต้องพึ่งการจดบันทึก
- **ราคาที่ต้องบันทึกไว้ตรง ๆ:** ค่านี้ **เดาได้โดยไม่ต้องเข้าใกล้ beacon เลย** —
  ใครที่เดาถูกว่าเราใช้ namespace DNS + `www.bigc.co.th` ก็คำนวณ UUID ของทั้งฟลีต
  ได้ทันที ต่างจากค่าสุ่มที่ต้องดักฟัง broadcast ก่อนถึงจะรู้
  **แต่ไม่เปลี่ยนระดับความเสี่ยงที่เอกสารนี้ยอมรับไว้แล้ว** เพราะ payload ของ
  iBeacon เป็น plaintext ที่ใครอยู่ในระยะก็อ่านค่า UUID ได้อยู่แล้ว และการปลอม
  (spoofing) ถูกบันทึกเป็น **known accepted risk** ใน ADR-5 ตั้งแต่ต้น —
  proximity UUID **ไม่ใช่กลไกความปลอดภัย และห้ามใช้เป็นกลไกความปลอดภัย**
  สิ่งที่เปลี่ยนไปคือ "ต้นทุนของการรู้ค่า" ลดจาก "ต้องเดินไปดักฟัง" เหลือ "เดาชื่อ
  ให้ถูก" ซึ่งไม่มีผลกับการออกแบบใด ๆ ในโปรเจกต์นี้ที่พึ่ง UUID เป็นความลับ
  (ไม่มีเลย)

### การตรวจสอบว่าเป็น UUID v5 จริง (ตรวจจากบิตของค่านี้เอง)

ค่า: `89E2EDDA-D2C9-52F1-BC39-3489CC37E1EF` แบ่งเป็น 5 กลุ่มตามมาตรฐาน UUID (`8-4-4-4-12` hex digits):

| กลุ่มที่ | ค่า |
|---|---|
| 1 | `89E2EDDA` |
| 2 | `D2C9` |
| 3 | `52F1` |
| 4 | `BC39` |
| 5 | `3489CC37E1EF` |

- **Version nibble** ต้องเป็นตัวอักษรตัวแรกของกลุ่มที่ 3 — กลุ่มที่ 3 คือ `52F1` → ตัวแรกคือ **`5`** ตรงกับ version 5 (name-based, SHA-1) ✅ ผ่าน
- **Variant nibble (RFC 4122)** ต้องเป็นตัวอักษรตัวแรกของกลุ่มที่ 4 และต้องอยู่ในเซ็ต `{8, 9, a, b}` — กลุ่มที่ 4 คือ `BC39` → ตัวแรกคือ **`B`** ซึ่งอยู่ใน `{8,9,a,b}` ✅ ผ่าน

ยืนยันซ้ำจากไลบรารีโดยตรง (ไม่ใช่การนับ nibble ด้วยตาอย่างเดียว):

```bash
python3 -c "import uuid; u=uuid.uuid5(uuid.NAMESPACE_DNS,'www.bigc.co.th'); print(u.version, u.variant)"
# 5 specified in RFC 4122
```

**สรุป:** ค่า `89E2EDDA-D2C9-52F1-BC39-3489CC37E1EF` ตรวจแล้วเป็น UUID v5 (RFC 4122 variant) จริงจากบิตของมันเอง **และ** derive ซ้ำได้จากชื่อโดเมน ไม่ใช่การอ้างลอย ๆ

## สถานะและขอบเขตการใช้งาน

- นี่คือ **proximity UUID เดียวทั้งบริษัท** ตามสคีมที่ ADR-5 กำหนด (`ARCHITECTURE.md` → "ADR-5: BigC ID Scheme สำหรับ multi-vendor provisioning" → "โครง ID 3 ชั้น" → "1. Proximity UUID — เดียวทั้งบริษัท (ข้อบังคับ)") — ใช้ค่านี้ค่าเดียวสำหรับทุกอุปกรณ์/ทุกยี่ห้อในฟลีต BigC เพื่อให้ `CLBeaconIdentityConstraint(uuid:)` แบบไม่ระบุ major/minor (wildcard) ครอบคลุมทั้งฟลีตด้วย 1 region เดียวได้ตามที่ ADR-5 พิสูจน์ไว้
- Major และ Minor เป็นเลขรันล้วนตามที่ ADR-5 ตัดสินใจแล้ว (ตัวเลือก B) — การกำหนดค่า major/minor จริงต่ออุปกรณ์เป็นงาน provisioning แยกต่างหาก (ยังไม่ scope ของไฟล์นี้ ค่า mapping major/minor → ยี่ห้อ/ล็อต/กลุ่ม/ตำแหน่ง เก็บใน backend/database ตามที่ ADR-5 กำหนด ไม่ใช่ในเอกสารนี้)
- ค่านี้ยังไม่ถูกนำไปตั้งค่าใน production build ใด ๆ ณ วันที่บันทึกนี้ — เป็นเพียงการ generate ค่าไว้ล่วงหน้าตามข้อบังคับของ ADR-5 ก่อน provision อุปกรณ์จริงล็อตแรก ทีมที่จะนำไปตั้งค่า config ของ production build ต้องอ้างอิงจากไฟล์นี้เท่านั้น ห้าม generate ค่าใหม่ซ้ำเอง
