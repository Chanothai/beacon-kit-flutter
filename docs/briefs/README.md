# docs/briefs

โครง/บรีฟงานเอกสารก่อนลงมือเขียนจริง — ผลจากขั้น `beacon-architect` ของ
`PIPELINE.md` เก็บไว้ให้ตรวจสอบย้อนหลังได้ว่าทำไมเอกสารจริงถึงออกมาแบบนี้

ตั้งชื่อไฟล์ `<YYYY-MM-DD>_<เรื่อง>.md` แต่ละไฟล์ต้องมีหัวระบุ branch/base
commit/สถานะกำกับไว้ ไฟล์เหล่านี้**ไม่ใช่**เอกสารอ้างอิงถาวร — เมื่องานเสร็จ
และ merge แล้ว ให้เนื้อหาจริงใน README/ARCHITECTURE เป็นความจริงหลักเสมอ
